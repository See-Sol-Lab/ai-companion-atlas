What is DeepSeek GUI?

DeepSeek GUI is See-Sol-Lab's Windows-native AI workbench built on DeepSeek Harness. Harness takes care of sessions, tools, permissions and runtime; DeepSeek GUI 1.1.1 complements first boot, built-in browser, file sidebar, in-place updates, data migration and archive session management on top of the workbench.

In one sentence:Work with the Agent in session and check project status directly from the side; still have access to Harness' Profiles, plugins, and terminal when needed.

Installation

Download from DeepSeek GUI official website DeepSeekGUI-Setup-1.1.1.exe. The installer installs according to the current Windows user, and ordinary user rights are sufficient.

  1. Double-click the installation package.
  2. After the file installation is complete, the DeepSeek GUI will start automatically.
  3. The DeepSeek GUI can then be opened from the desktop or start menu.

The distribution package comes with the DeepSeek Harness runtime, Node.js and pnpm are already in it.

First time configuration

A fresh installation walks through selecting a workspace, connecting to the model, and sending the first message. Can be skipped at any time; users with existing session data will not be treated as new users.

1. Configuration model

Open the settings in the lower left corner and enter Model. Fill in the DeepSeek API key and select the model available for the account; the v1.1.1 built-in directory contains DeepSeek V4.1 Flash that supports image input. Credentials are saved by Harness in the DeepSeek GUI data directory and do not enter the installation package, command line, or general diagnostic logs.

2. Select workspace

Return to the homepage and select a project folder as the workspace. Just leave the project where it is, and the Agent will work directly in the workspace you selected.

3. Create or restore a session

Create a new session after selecting the model and workspace. Existing Harness sessions, Profiles, and configurations continue to be managed by the same runtime.

Local Workbench

After entering the session, you can switch to "Change", "Git" and "Memory" next to "Conversation" and "Track". These views read local state directly, and normal refresh does not require additional requests to the model.

  • Changes:Group commits, changed files, new files and conflicts to view a single file diff; open it in the right file bar when positioning is required.
  • Git：The upper half views the parallel workspace, and the lower half views branches, remotes, leading/behind numbers, and recent commits; commit, push, and PR results will also remain in the current session record.
  • Memory:Read the Markdown memory of the current project, open the file location, or continue maintenance through "Let Assistant Organize".

Git and Pull Request

Dedicated Git tools support viewing status and diffs, staging, unstaged, undoing unstaged changes to tracked files, and creating commits. The remote end, target branch, and commits to be pushed will be displayed before pushing; creating a PR uses the Git and GitHub CLI credentials already in your computer.

Built-in browser and file sidebar

When the assistant opens a public web page, the built-in browser automatically expands to the right of the session. It supports realistic rendering, snapshots, screenshots and interactions; logins, form submissions and other sensitive actions still require user approval.

The browser and the Sidebar on the right side of Harness are displayed alternately. Sidebar provides multi-tab and column preview of code, Markdown, HTML, PDF, and images; it is also accessed when opening files from changes or tool results.

Picture reading ability:When the text model is asked to view a web page or screenshot, it will first ask whether to switch models and will not pretend to have seen it.

Global memory and project memory

Global memoryLocated in "Settings → Global Memory", it is used to save personal preferences and collaboration requirements across projects. It is edited by the user and is read-only by the assistant.

Project memorysaved in the selected workspace <folder name>.memory.md, used to record project decisions, commitments, and user revisions, maintained by the assistant within the current workspace.

The two-layer memory will enter the context when the session is loaded, and the actual content used is saved with the session record. If the development version ever left project-level memory.md, please merge the content that needs to be retained into a new project memory file with a folder name prefix.

Harness and Profiles

Model, session, credentials, permissions, memory, and hook state are all managed by Harness. The current Harness Home and Profile are controlled by the desktop launcher; v1.1.1 embeds DeepSeek Harness 0.1.5-rc.2.

  • Managed Home：By default, DeepSeek GUI's own application data directory is used.
  • Existing Home：Advanced users can explicitly select an existing Harness Home; the DeepSeek GUI does not automatically migrate, merge, or rewrite it.
  • Profile：Harness profile can be switched; when switching fails, the last-known-good status is retained for recovery.

Terminals and plug-ins

When you need deeper control, you can open the DSH Terminal. DeepSeek GUI prepares private for terminal dsh / node / pnpm Entry without modifying system PATH, registry or shell configuration.

Plug-in management continues to be Harness official dsh plugin path. DeepSeek GUI does not mistake "loaded in package.json" for "plugin has actually been loaded", and distinguishes between Profile Bundles, installed dependencies and the true status of Loader.

Update in place

Check for updates from the menu or tray. DeepSeek GUI will download the installation package in the background, check the HTTPS address, file size and SHA-256, and display the version and update instructions; the Windows installer will only be launched after user confirmation.

Automatic downloading is on by default and can be turned off in the update panel. Canceling the installation will retain the verified installation package, so there is no need to download it again next time; the file will be checked again before being handed over to the installer.

Data and Offload

By default, the packaged version puts Harness data in %APPDATA%\DeepSeekGUI\dsh, which includes credentials, settings, sessions, Profiles and global memory. The DeepSeek GUI's launcher and window preferences are also saved in its own userData directory; project memory remains in the corresponding workspace.

"Data Location" in the menu can migrate Managed Harness Home. The program is first copied and verified one by one. After switching, Harness is restarted. After the verification is successful again, it will be asked whether to delete the old copy; the Existing Home, project directory and application installation location will not be moved accordingly.

Archived conversations are located in "Settings → Archived Conversations" and can be restored and opened; permanent deletion requires two-step confirmation and will wait for the current reply and tool execution to complete.

v1.1.1 will migrate the session data to V3 when opening an old session for the first time and retain the original files; the migrated session can no longer be read by the old version of Harness.

Ordinary uninstallation will ask whether to delete %APPDATA%\DeepSeekGUI and the migrated data directory. After selecting Keep, you can continue to use the original credentials, settings, and sessions when reinstalling; upgrade and replacement will preserve the data.

Troubleshooting

Port 3080 is occupied

DeepSeek GUI is currently fixed on the local machine 127.0.0.1:3080 Start the Harness service. When the port is occupied by other programs, an error will be clearly reported instead of secretly changing the port.

Harness startup failed

The packaged version of the diagnostic log is located in the DeepSeek GUI application data directory. Harness service log and bounded rotation deepseekgui-main.log will desensitize common API keys, Bearer tokens and other credential forms; you can export a local diagnostic package from "Settings → BUG Diagnosis and Feedback" or ask the assistant to conduct a redaction triage.

Why is the window still there after it is closed?

Closing the upper right corner of the window only hides the window, and Harness continues to run in the system tray. To actually stop the runtime, use the tray or menu Quit DeepSeek GUI。

Run from source

The shortest path for developers:

pnpm install
pnpm run build
pnpm run dev:desktop

dev:desktop will start the local DSH web service and open the DeepSeek GUI Desktop. More complete architecture and development documentation remains in the GitHub repository.
