DeepSeek GUI 文档

当前版本 1.1.2 内嵌官方 Harness 0.1.7，支持 DeepSeek 账号登录，包含本地 Workbench、工程记忆、本地技能库、内置浏览器、右侧文件栏、就地更新和受保护位置审批。

DeepSeek GUI 是什么

DeepSeek GUI 是 See-Sol-Lab 基于 DeepSeek Harness 构建的 Windows 本地 AI 工作台。Harness 负责会话、工具、权限和运行时；DeepSeek GUI 1.1.2 在工作台之上加了账号登录与用量、工程记忆、本地技能库、内置浏览器、文件侧栏、就地更新、数据迁移和受保护位置审批。

一句话：在会话里与 Agent 一起工作，在旁边直接检查项目状态；需要时仍能进入 Harness 的 Profiles、插件和终端。

安装

从 DeepSeek GUI 官网下载 DeepSeekGUI-Setup-1.1.2.exe。安装器按当前 Windows 用户安装，普通用户权限就够。

  1. 双击安装包。
  2. 文件安装完成后，DeepSeek GUI 会自动启动。
  3. 之后可以从桌面或开始菜单打开 DeepSeek GUI。

发行包自带 DeepSeek Harness 运行时，Node.js 和 pnpm 都已经在里面了。

首次配置

第一次打开时，如果既没有登录账号，也没有配置任何 API Key，会先看到欢迎页：可以用 DeepSeek 账号登录、添加 API Key，或稍后配置。已经配置过 API Key 的用户不会看到欢迎页。

1. 登录或填入 API Key

用账号登录时，DeepSeek GUI 会打开系统浏览器完成登录，然后回到应用；账号会话使用账号额度，不需要 API Key。登录后由官方引导介绍额度、了解用途，并选择工作过程显示多少细节。也可以在欢迎页或「设置 → 模型」中填入 API Key。凭据由 Harness 保存在 DeepSeek GUI 数据目录中，不进入安装包、命令行或普通诊断日志。

2. 选择工作区

返回首页，选择一个项目文件夹作为 workspace。项目留在原地就行，Agent 直接在你选的这个工作区里干活。

3. 新建或恢复会话

选择模型与工作区后新建会话。已有 Harness 会话、Profiles 与配置继续由同一个运行时管理。

账号与用量

「设置 → 账号与余额」显示账号、充值余额与赠金余额；「查询用量」和「充值」会在窗口内打开 DeepSeek 平台页面，已经是登录状态。

同一页下方是 DeepSeek GUI 的用量视图：今天、7 天、30 天的花费、请求数、token 用量与缓存命中率，以及 60 天的活动热力图。数据直接用账号登录读取，令牌不会进入任何页面。

已知问题：账号卡片可能显示「账号资料暂不可用」，不显示昵称与头像；余额、用量与充值不受影响。

本地 Workbench

进入会话后，可以在「对话」「轨迹」旁切换「改动」「Git」「项目管理」「记忆」。这些视图直接读取本地状态，普通刷新不需要额外请求模型。

  • 改动：按将提交、已改动、新文件和冲突分组，查看单文件 diff；需要定位时在右侧文件栏中打开。
  • Git：上半部分查看并行工作区，下半部分查看分支、远端、领先／落后数量与最近提交；提交、推送和 PR 结果也会留在当前会话记录中。
  • 项目管理：按项目勾选这个文件夹下的会话可以使用哪些本地技能。
  • 记忆：阅读当前项目的 Markdown 记忆，或在增强记忆模式下查看、编辑、忘掉和恢复记忆条目。

Git 与 Pull Request

专用 Git 工具支持查看状态和差异、暂存、取消暂存、撤销已跟踪文件的未暂存改动，以及创建提交。推送前会显示远端、目标分支和待推送提交；创建 PR 使用电脑里已有的 Git 与 GitHub CLI 凭据。

内置浏览器与文件侧栏

助手打开公开网页时，内置浏览器会自动在会话右侧展开。它支持真实渲染、快照、截图与交互；登录、表单提交和其他敏感动作仍需用户批准。

浏览器与 Harness 右侧 Sidebar 交替显示。Sidebar 可用多标签与分栏预览代码、Markdown、HTML、PDF 和图片；从改动或工具结果打开文件时也会进入这里。

看图能力：文本模型被要求查看网页或截图时会先询问是否切换模型，不会假装已经看见。

全局记忆与项目记忆

全局记忆位于「设置 → 全局记忆」，用于保存跨项目的个人偏好与协作要求，由用户编辑，助手只读。

项目记忆保存在所选工作区的 <文件夹名>.memory.md，用于记录项目决策、约定和用户修正，由助手在当前工作区内维护。

两层记忆会在会话加载时进入上下文，实际使用的内容随会话记录保存。如果开发版曾留下项目级 memory.md，请把需要保留的内容合并到新的带文件夹名前缀的项目记忆文件。

增强记忆（实验性）：在「设置 → 全局记忆」中可以改用带版本的记忆条目。助手可以记下、更正、忘掉和检索，每一步只注入与当前内容相关的条目；你可以查看、编辑、撤销和恢复。默认仍是 Markdown 文件，切换前会先确认，随时可以切回。

本地技能库

在「设置 → Skill」中可以从文件夹、ZIP 或单个 Markdown 文件导入技能。导入前会先审阅，可以当场修正元信息（只改技能库里的副本），有阻断问题时不会装入。

会话顶部的「项目管理」页按项目勾选可用的技能：同一文件夹下的会话共用一份选择，没勾选的技能对这个项目不可见，官方原有的技能不受影响。

安全保护

  • 受保护位置：助手的命令或文件写入涉及 Windows 系统文件、已安装的程序或 DeepSeek GUI 自己的代码时，会弹出红色审批卡，「完全访问」下也一样；按回车不会放行，焦点默认在「拒绝」。这项检查是启发式的，写在脚本文件里的路径识别不到。
  • 只能聊天的工作区：用户目录、盘符根目录和系统目录作为工作区时只读，不能开启完全访问或提权。
  • 管理员运行：以管理员身份启动时会弹出红色警告；继续使用时禁用「完全访问」。
  • .git 默认只读：「工作区内修改」模式下写入 .git 会被拒绝，暂存与取消暂存会先弹出审批。

Harness 与 Profiles

模型、会话、凭据、权限、记忆和 hook 状态都由 Harness 管理。当前的 Harness Home 和 Profile 由桌面启动器控制；v1.1.2 内嵌 DeepSeek Harness 0.1.7-rc.2。

  • Managed Home：默认使用 DeepSeek GUI 自己的应用数据目录。
  • Existing Home：高级用户可以显式选择已有 Harness Home；DeepSeek GUI 不自动迁移、合并或改写它。
  • Profile：可以切换 Harness profile；切换失败时保留 last-known-good 状态用于恢复。

终端与插件

需要更深层控制时，可以打开 DSH Terminal。DeepSeek GUI 为终端准备私有的 dsh / node / pnpm 入口，不修改系统 PATH、注册表或 shell 配置。

插件在官方插件页管理：可以安装、配置、启停和卸载，安装时会检查与当前 Harness 版本是否兼容。DeepSeek GUI 随包的插件显示在「DeepSeekGUI 内置」分组中，不可卸载。

就地更新

从菜单或托盘检查更新。DeepSeek GUI 会在后台下载安装包，核对 HTTPS 地址、文件大小与 SHA-256，并展示版本与更新说明；只有用户确认后才会启动 Windows 安装器。

自动下载默认开启，可在更新面板中关闭。取消安装会保留已经校验的安装包，下次无需重新下载；交给安装器之前还会再次核对文件。

无法访问 GitHub 时，会自动改从官网下载同一个安装包，并经过同样的 SHA-256 与大小校验。

数据与卸载

打包版默认把 Harness 数据放在 %APPDATA%\DeepSeekGUI\dsh，其中包括凭据、设置、会话、Profiles 与全局记忆。DeepSeek GUI 的 launcher 和窗口偏好也保存在自己的 userData 目录；项目记忆留在对应工作区。

菜单中的「数据位置」可以迁移 Managed Harness Home。程序先复制并逐项校验，切换后重启 Harness，再次核对成功后才会询问是否删除旧副本；Existing Home、项目目录和应用安装位置不会跟着搬。

归档会话位于「设置 → 已归档的会话」，可以恢复并打开；永久删除需要两步确认，并会等待当前回复与工具执行结束。

v1.1.2 首次打开旧会话时会把会话数据转换为 V4 格式；转换后的会话不能再被 v1.1.1 读取。

普通卸载会询问是否删除 %APPDATA%\DeepSeekGUI 及已迁移的数据目录。选择保留后，重装时可以继续使用原来的凭据、设置和会话；升级替换会保留数据。

故障排查

端口 3080 被占用

DeepSeek GUI 当前固定在本机 127.0.0.1:3080 启动 Harness 服务。端口被其他程序占用时会明确报错，而不是偷偷换端口。

Harness 启动失败

打包版诊断日志位于 DeepSeek GUI 应用数据目录。Harness 服务日志与有界轮转的 deepseekgui-main.log 会对常见 API key、Bearer token 等凭据形态做脱敏；可以从「设置 → BUG 诊断与反馈」导出本地诊断包或让助手进行一次脱敏分诊。

项目文件夹里的程序启动不了

用「工作区内修改」模式跑过 Windows 沙箱的文件夹，会被官方沙箱永久标记为 Low 完整性，之后从里面启动的程序（例如 Electron 开发构建）可能无法运行。现象与清理方法见 GitHub 仓库中的故障排查指南。

窗口关闭后为什么还在

窗口右上角关闭只是隐藏窗口，Harness 继续在系统托盘运行。要真正停止运行时，请使用托盘或菜单中的 Quit DeepSeek GUI。

从源码运行

面向开发者的最短路径：

pnpm install
pnpm run build
pnpm run dev:desktop

dev:desktop 会启动本地 DSH Web 服务并打开 DeepSeek GUI Desktop。更完整的架构与开发文档保留在 GitHub 仓库中。

许可与上游

DeepSeek GUI 是 DeepSeek Harness 的非官方社区产品，与 DeepSeek 无隶属关系，也未获其背书。Harness 和官方 Web UI 属于 DeepSeek。

仓库采用分层许可：上游 DeepSeek Harness 及上游衍生内容继续保留 MIT；See-Sol-Lab 原创桌面/产品层在明确范围内采用 PolyForm Perimeter 1.0.1。个人、教育、研究、兴趣与允许的内部使用均可；向他人提供与 DeepSeek GUI 竞争的替代产品需要另行授权。
